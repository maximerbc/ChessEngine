# Contributing

Start with the [README](README.md), [research map](docs/research.md), and [development checks](docs/development.md). Small, focused changes with a clear explanation and relevant validation are easiest to review. Use GitHub issues for ordinary bugs or suggestions when the repository is accessible; use the security process below for sensitive reports.

Preserve full legal move histories, automatic draws, model/schema checks, frozen protocols, and negative evidence. Keep teacher labels, human-move targets, position values, and playing-strength evidence distinct. Do not train on validation/test records or promote a model through an unrelated fix. Detailed standing rules are in [AGENTS.md](AGENTS.md).

Never commit credentials, raw datasets, optimizer/resume checkpoints, local environments, or backup archives. Existing tracked inference artifacts have explicit research/release identities; changing their publication policy requires review. Run secret scanning before submitting changes; see [SECURITY.md](SECURITY.md).

No paid training or hosting, remote push, deployment, or repository visibility change is implied by a contribution. The repository owner handles publication actions.
